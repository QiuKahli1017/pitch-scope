# PitchScope · 实时音高识别

Windows 桌面音高识别工具。切换 **电脑内部声音** 和 **麦克风**，实时查看音名、频率、音准偏差与音高变化。

> **本项目采用 vibe coding（vibecoding）方式开发：由用户描述需求，AI（OpenAI Codex）协助编写代码、调试和整理文档。** 这是一个可继续改进的开源项目，识别结果应结合实际听感使用。

## 下载和运行

- 在 [Releases](https://github.com/QiuKahli1017/pitch-scope/releases) 下载 `PitchScope-Windows-x64.zip`。
- 解压后双击 `PitchScope.exe`，**无需安装 Python**。
- 支持 **Windows 10 / 11，64 位**。当前版本不支持 macOS / Linux。
- 程序未做商业代码签名。

## 功能

| 功能 | 说明 |
| --- | --- |
| 电脑内部声音 | 使用 Windows WASAPI loopback，直接采集选定扬声器或耳机播放的声音；无需虚拟声卡或“立体声混音” |
| 麦克风 | 采集选定麦克风，适合哼唱、练声和乐器单音调音 |
| 模式与设备切换 | 识别过程中切换模式或设备，会释放旧音频流并打开新设备 |
| 实时音高 | 显示基频（Hz）、音名和八度，例如 A4、C4、F♯3 |
| 音准指示 | 显示相对最近音符的音分偏差；负值偏低、正值偏高，±5 cents 区域以绿色标记 |
| 音高曲线 | 展示最近约 12 秒的音高变化；静音或不稳定信号会断开曲线 |
| 信号反馈 | 显示输入电平与周期性置信度；置信度不是统计意义上的准确率 |
| 调整参数 | A4 基准可设为 400–480 Hz；静音门限可设为 -80 至 -20 dBFS，停止后修改 |
| CSV 导出 | 导出本次打开程序以来最近 36,000 条有效记录，包含时间、模式、设备、频率、音名、音分、置信度、电平和 A4 基准 |
| 本地处理 | 不上传、不保存原始音频；识别记录仅保存在内存中，点击导出才写入 CSV |
| 快捷键 | 空格开始 / 停止识别（编辑参数时不触发） |

## 使用方法

### 识别电脑播放的声音

1. 选择 **电脑内部声音**。
2. 在设备列表中选择正在播放声音的扬声器或耳机，通常是带“默认”标记的设备。
3. 点击 **开始识别**，播放清晰的单音、独奏或人声。
4. 查看当前音高及曲线；结束后点击 **停止识别**。

采集范围是**整个所选输出设备**，并非只采集某一个应用。蓝牙耳机连接或默认输出改变后，请点击“刷新设备”并重新选择。

### 识别麦克风

1. 确认麦克风已连接、启用，并允许桌面应用访问麦克风。
2. 选择 **麦克风** 及对应输入设备，点击 **开始识别**。
3. 对麦克风持续哼唱一个音，或演奏一个乐器单音。
4. 输入太弱时可适当降低静音门限，例如从 -55 改成 -65 dBFS；环境噪声较大时可提高门限。

### 音高范围与限制

- 目标识别范围为 **50–2000 Hz**，使用 FFT 加速的 YIN 基频估计和少量显示平滑。
- 适用于**单音或明显主导的周期信号**。和弦、完整歌曲、多个人声、鼓声或强混响可能无法识别，或发生八度误判；本软件不做多音转谱、和弦识别或人声分离。
- 静音、气声和纯噪声通常不显示音符。音频捕获、分析窗口及驱动都会引入延迟；低音需要更长的周期信息。
- 立体声选择能量较强的声道进行分析，以避免反相抵消；两个声道内容差异较大时可能发生主导声道切换。
- 不自动修改系统音量、默认音频设备或隐私权限。

## 从源码运行

安装 [Python 3.12 x64](https://www.python.org/downloads/windows/)，在项目目录运行：

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe main.py
```

也可以双击 `run.bat`，它会创建本项目的虚拟环境、安装依赖并启动。首次安装依赖需要联网；运行识别本身无需联网。

## 测试

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

自动测试涵盖多种音高与采样率、强二次泛音、静音和噪声拒绝、直流偏置、音名与音分转换，以及反相立体声。合成信号测试中的频率误差检查不代表任意真实录音的精度保证。

实机验证中，已确认 Windows 默认输出的回环音频可采集。麦克风仍依赖本机设备状态与隐私权限；它的自动算法测试不能替代真实输入设备验收。

## 构建 EXE

在已激活的 Python 3.12 虚拟环境中运行：

```powershell
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python -m PyInstaller --noconfirm --clean --onefile --windowed --name PitchScope --collect-all pyaudiowpatch main.py
```

生成文件为 `dist/PitchScope.exe`。也可运行 `build.ps1`。GitHub Actions 会测试和构建 Windows 可执行文件，并提供构建产物下载；推送 `v*` 标签时会发布 ZIP 到 Releases。

## 常见问题

**设备列表中有设备，但无法打开？**

设备枚举不保证设备当前可用。检查是否断开、禁用或被其他程序独占；重新连接后刷新。麦克风还需检查“Windows 设置 → 隐私和安全性 → 麦克风 → 允许桌面应用访问麦克风”。错误码来自音频驱动，单凭错误码无法确定原因。

**电脑有声音，界面却一直等待？**

确认选择了实际输出设备；例如声音从耳机播放时，不应选择显示器或另一组扬声器。完整伴奏可能没有清晰的单一基频，可先用独奏长音验证。

**停止后曲线消失，CSV 还有记录吗？**

曲线是最近 12 秒的滚动视图。有效音高记录在切换模式和停止后仍保留；达到 36,000 条时淘汰最旧记录。关闭程序会清空未导出的记录。
